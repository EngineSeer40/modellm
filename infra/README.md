# First release

This deploys the current application, with **one task and one Streamlit process**, to ECS Fargate in `ap-southeast-2`. No AWS resources have been created by the implementation. Uploads, results, sessions and daily counters are ephemeral. A replacement loses them; deploy during a quiet window. Stop-first replacement intentionally causes brief downtime.

The release uses existing cache boundaries, SDK tools/validators, cost-experiment flags and consolidated UI. It adds procedural helpers rather than implementing the larger maintainability refactor. See [deployment spec](../todo/20261015_first_release_deployment_spec.md).

## Local checks

```sh
uv sync --frozen --extra dev
uv run --frozen --extra dev pytest -q
uv lock --check
uvx --from cfn-lint==1.40.2 cfn-lint infra/service.yaml infra/bootstrap.yaml infra/deployment-roles.yaml
docker build --platform linux/amd64 --build-arg GIT_SHA=local -t modellm:release-smoke .
bash infra/smoke.sh modellm:release-smoke
```

The smoke test uses no AWS credentials or network: non-root, read-only root, image-owned writable volumes, real restricted dbt build/tests, concurrent web health checks, and a supervised worker with deliberate ingestion failure. It deletes its own container/volumes. Ordinary CI never invokes Bedrock.

Run locally with `uv run streamlit run app.py`. To use a `.env` file, copy the settings you need from [`.env.example`](../.env.example) and start with `uv run --env-file .env --frozen streamlit run app.py`; the original command does not explicitly load `.env`. The complete example pins production limits: setting PROD false while leaving numeric overrides in place retains those limits. `MODELLM_PROD` defaults to `false`; optional release caps are unset unless explicitly configured. The same workspace, SQL policy and worker supervisor remain active. `MODELLM_LIVE_ENABLED=false` disables live runs in either mode. For production testing set `MODELLM_PROD=true`; live runs then default off. Set `MODELLM_LIVE_ENABLED=true` to allow public uploads and submissions. There is no password gate; `MODELLM_LIVE_ACCESS_CODE` is obsolete and ignored.

`ReleaseSettings` resolves limits once per app process and per standalone workflow. Use `MODELLM_<FIELD_NAME_UPPERCASE>` for numeric overrides, e.g. `MODELLM_MAX_MODEL_CALLS`, `MODELLM_MAX_COST_USD`, `MODELLM_RUN_SECONDS`, `MODELLM_DAILY_RUNS`, `MODELLM_WORKSPACE_BYTES`. Values must be positive; optional local limits are unset by default. The source lists all fields/defaults. CloudFormation exposes all 21 numeric run settings, including upload/source limits and retention; include overrides in CFN_PARAMETERS to tune these without rebuilding. ECS template defaults match the local configuration reviewed on 27 October 2026: 20 runs/day, USD 2 estimated cost/run, 4 analyses, 5 charts, 20,000 rows and 30 columns per file, 20 MiB per file, 60 MiB total, and 86,400-second retention. LiveEnabled defaults to true; LangfuseBaseUrl defaults to https://jp.cloud.langfuse.com. Telemetry is enabled only when LangfuseSecretArn supplies the credentials. Existing CFN_PARAMETERS values and previously saved stack parameter values override template defaults; update them to the values in `infra/parameters.json.example` when aligning an existing stack. A local `.env` is excluded from the image and does not configure ECS. The 2–6 file count is hard-coded in UI, submission and ingestion, with no environment override. Legacy `MODELLM_DUCKDB_RETENTION_DAYS` and `MODELLM_DUCKDB_BUDGET_BYTES` affect only an unused database-only helper, not live cleanup. Restart the process after changing configuration. `MODELLM_COST_EXPERIMENTS` remains independent of PROD. All six measures are enabled when it is unset; an explicit empty value disables them for A/B testing, and a comma-separated subset selects individual measures. CloudFormation and the parameter example enable all six by default. Existing saved deployment parameters remain explicit overrides, so update any previously blank CostExperiments value. Main stages default to Sonnet 4.6 (`au.anthropic.claude-sonnet-4-6`), while plotting retains its explicit Haiku 4.5 choice. Model IDs can be overridden with `MODELLM_BEDROCK_MODEL_ID` and `MODELLM_PLOTTING_MODEL_ID`; production rejects unknown pricing when the cost guard is enabled. Add verified prices before changing to an unpriced model. Cost limits use **reported list-price estimates**, allow the current response to finish, and are not AWS invoice caps. Missing usage stops further model calls. Native Bedrock token counting is off.

Pricing is maintained in `src/usage.py`, with one calculation shared by reported totals and the live budget. For a US Sonnet 5.5 trial, use the following overrides and restart (select `us.anthropic.claude-sonnet-5` for Sonnet 5):

```dotenv
AWS_REGION=us-east-1
MODELLM_BEDROCK_MODEL_ID=us.anthropic.claude-sonnet-5-5
MODELLM_PLOTTING_MODEL_ID=us.anthropic.claude-haiku-4-5-20251001-v1:0
```

The single AWS_REGION setting configures all model clients; use a plotting profile available from that region too. This changes the Bedrock client region, independently of where Streamlit runs. For ECS, update ModelId, PlottingModelId and BedrockResourceArns for both profiles and their destination models. The template supplies AWS_REGION from its stack region, so a Sydney stack also needs its container AWS_REGION changed to a supported US source region before trying these US profiles. Confirm account access and routing with GetInferenceProfile from the selected source region; local pricing support does not establish live availability. The [Bedrock model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5-5.html) documents US source/destination regions. Sonnet 4.6 remains the default; plotting keeps its own model selection.

US and AU Sonnet 5.5 estimates per million tokens: $2.20 input, $11 output, $2.75 five-minute cache writes, $0.11 cache reads; global: $2, $10, $2.50, $0.10. Prices were verified on 15 October 2026 using [Anthropic pricing and geographic premium](https://platform.claude.com/docs/en/about-claude/pricing) and the [AWS cache-price update](https://aws.amazon.com/bedrock/pricing/).

The existing AU/global pricing entries remain supported where those profiles are available to the account. Sonnet 5 input, output and five-minute cache-write estimates match 5.5, but cache reads cost $0.22 per million tokens for US/AU and $0.20 globally. US Haiku 4.5 estimates match AU: $1.10 input and $5.50 output per million tokens, with the existing cache multipliers.

Sonnet 5 and 5.5 require provider-default sampling. Only 5.5 needs automatic tool choice: a small adapter over the public SDK stream method preserves structured-output retries/validators while keeping tool choice automatic, including the SDK's fallback. Sonnet 5 retains the native SDK tool-choice behavior. Both retain provider-default adaptive thinking (high effort), whose tokens count toward the existing output and cost limits. These compatibility paths are tested locally with SDK stubs; actual account access and a first real model invocation still need verification. See the [migration guide](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide). No live Bedrock call is performed by ordinary tests.

All workspace files count toward the 2 GiB budget. Inputs are deleted on terminal exit, other owned artifacts expire 24 hours after the last result update or earlier size eviction. Cleanup runs at manager startup, hourly while the process is alive, before admission, around run execution and after supervision. This permits roughly one hour of expiry lag during idle service operation. Copied input files are removed on success/failure; browser upload drafts remain in session memory until cleared or the session ends. Active storage is checked by the supervisor every five seconds; this permits some overshoot. Old unmarked local runs count toward usage but are never automatically deleted. Admission rejects when they leave insufficient space. Remove/archive those intentionally outside this release's cleanup. No global private-run browser is provided.

## Operator bootstrap

1. Supply an existing VPC, **two public subnets in different AZs**, their internet-gateway routes, an ACM certificate in Sydney and a hostname. Configure DNS to the ALB output after creation. Existing private subnets/NAT can replace the production networking later. Security groups allow task ingress only from the ALB.
2. No access-code secret is required. The deprecated `PreviewSecretArn` parameter is accepted for compatibility but is unused; the task no longer fetches it. Optional Langfuse credentials still use Secrets Manager and may require `SecretKmsKeyArn`. LiveEnabled defaults to true for public submissions; set it to false to disable them.
3. Bootstrap the immutable, scan-enabled ECR repository:

   ```sh
   aws cloudformation deploy --region ap-southeast-2 --stack-name modellm-images --template-file infra/bootstrap.yaml
   aws cloudformation describe-stacks --region ap-southeast-2 --stack-name modellm-images --query 'Stacks[0].Outputs'
   ```

4. Verify Bedrock model access for both configured models. For each inference profile, resolve it with `aws bedrock get-inference-profile --region ap-southeast-2 --inference-profile-identifier <profile-id>`. Put the returned inference-profile ARN and **every destination model ARN** into `BedrockResourceArns`. Account SCPs must allow those destination regions. The app task gets only InvokeModel/InvokeModelWithResponseStream for those resources; no S3, Secrets Manager or ECS privileges. Execution role separately pulls ECR, writes logs and reads optional telemetry secrets. The app never uses execution-role credentials.
5. Follow [the first-release walkthrough](../todo/20261015_first_release_deployment_runbook.md#2-perform-your-first-release) for the ordered AWS console setup and exact GitHub values. It uses `infra/deployment-roles.yaml` to create the three deployment roles and a restricted programmatic IAM user. GitHub stores its access-key pair in environment secrets and assumes those same roles; no OIDC provider or advanced account activation is required. Initial IAM creation requires an administrator; do not grant PRs infrastructure privileges.
6. Copy `infra/parameters.json.example` into the protected `production` environment variable `CFN_PARAMETERS` after replacing placeholders. This is a JSON object of **non-secret** CloudFormation parameters. The example enables public submissions with `LiveEnabled=true`; set false to disable them. Set environment variables `STACK_NAME`, `CFN_ROLE_ARN`, `AWS_DEPLOY_ROLE_ARN`. In `release-build`, set `AWS_BUILD_ROLE_ARN`, `ECR_URI` (without tag), `ECR_REPOSITORY` (name). Region is fixed to Sydney in the workflow.
7. Merge a PR from this repository's `dev` branch into `master` to trigger `Deploy production` automatically. A closed, unmerged PR does not deploy. Keep both GitHub environments restricted to `master`; existing approval rules still apply. Manual runs from `master` remain available for parameter updates and retries. It tests, builds/smokes, pushes an immutable commit tag, resolves its digest, then updates **the CloudFormation stack's ImageUri** and checks HTTPS. ECR scans on push in the background; scans are advisory by default. To make scan completion and zero critical findings required, set `ECR_SCAN_BLOCK_RELEASE` to `'true'` in `.github/workflows/deploy.yml`. No new GitHub variables or IAM permissions are needed. CloudFormation remains the sole task-definition owner.

When Langfuse credentials are configured, new traces are public to anyone with the Results page’s “Langfuse Full Trace” link. `infra/deploy.py` explicitly sets `LangfusePublic=true`, including on existing stacks. This includes captured prompts and tool content. Previously private traces keep their existing visibility; this change applies to new worker runs after deployment.

`infra/service.yaml` has no DNS-zone ownership assumption; create an alias/CNAME from the supplied hostname to `AlbDnsName`. First deployment's final HTTPS check needs that DNS ready; if it fails solely because the new ALB hostname was not yet known, create DNS, then rerun the same commit (the existing immutable image is reused). BudgetEmail creates an account-wide monthly **alert**, not a hard stop or service-only charge attribution. Use a dedicated alert name per stack. ALB, Fargate, public IPv4, CloudWatch and ECR have idle charges.


If the first application creation ends in **ROLLBACK_COMPLETE**, correct the reported error before retrying. For a missing permission in `modellm-prod-cloudformation`, update **modellm-deployment-roles** using **Update stack → Replace current template → Upload a template file** and the corrected `infra/deployment-roles.yaml`. Keep existing parameters, acknowledge IAM changes, and wait for **UPDATE_COMPLETE**. Then delete only the failed **modellm-prod** stack and wait for deletion to finish. Run **Deploy production** manually from **master** to recreate it. Keep **modellm-images** and **modellm-deployment-roles**. A stack in ROLLBACK_COMPLETE cannot be updated; there is no running application to roll back to after a failed first creation.

### GitHub permission boundaries

`infra/deployment-roles.yaml` creates a programmatic IAM user with no console login and permission only to assume the two deployment roles. Those roles trust that user's exact ARN using `sts:AssumeRole`. The template does not create or output access keys. Create the key once in IAM and store it under **Environment secrets** as `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in both `release-build` and `production`; the existing role ARN variables remain unchanged. Never use root or administrator keys for this user. The key can assume both roles, so protect both environments and restrict their release branches. Rotate/delete the key through IAM and update both environments together. The workflow uses temporary role credentials for ECR and CloudFormation; it does not put the source key into the application image or ECS task.

This authentication method is supported by [configure-aws-credentials v4](https://github.com/aws-actions/configure-aws-credentials/tree/v4) and [programmatic IAM access in the new AWS experience](https://docs.aws.amazon.com/accounts/latest/reference/sign-up-for-aws.html). It replaces only the unavailable OIDC login step.

Build-role permissions: `ecr:GetAuthorizationToken` on `*`; on **the one repository ARN** allow BatchCheckLayerAvailability, InitiateLayerUpload, UploadLayerPart, CompleteLayerUpload, PutImage, DescribeImages, DescribeImageScanFindings. The repository has scan-on-push enabled; enhanced scanning requires adjusting the scan waiter/gate before enabling it.

Deploy-role permissions: CloudFormation Create/Describe/Execute/DeleteChangeSet, DescribeStacks, DescribeStackEvents, GetTemplate and GetTemplateSummary for **the one stack ARN** and the AWS CLI's change-set ARN prefix (`changeSet/awscli-cloudformation-package-deploy-*/*`). Permit `iam:PassRole` only for the dedicated CloudFormation service-role ARN, conditioned on `iam:PassedToService=cloudformation.amazonaws.com`. Grant the narrow read/list actions needed by the CLI if the account policy requires them; do not attach AdministratorAccess. It needs neither task-role assumption nor Bedrock/secret access.

The operator-owned CloudFormation service role trusts only `cloudformation.amazonaws.com`. Give it the resource creation/update actions used by `service.yaml` within this service's boundaries: ECS cluster/service/task definitions, ALB/listeners/targets, two security groups in the chosen VPC, seven-day log group, budget alert, and the two task IAM roles/policies. Restrict role passing to those two roles and `ecs-tasks.amazonaws.com`; enforce your account's permissions boundary on role creation if required. Some AWS create/describe actions require wildcard resources; bound them using account/region, tags and IAM boundary conditions where supported. Creating this role is deliberately not automated by the application's deploy role. Review the initial stack and role permissions with the operator before granting CI access.

## First cloud acceptance and rollback

Leave one task/process; never enable autoscaling or overlap tasks without redesigning admission/state. ALB stickiness does not make local quotas distributed. The service uses 2 CPU/4 GiB and image-defined writable `/data` and `/tmp` volumes; the rest is read-only. The Dockerfile's matching `VOLUME` directives preserve directory permissions for Fargate. `/_stcore/health` reports web-server health only.

After DNS/TLS and task startup: check task-role Bedrock invocation with a small workflow, reported/cache usage and build SHA; verify HTTPS WebSocket navigation, uploads/downloads, two-session busy isolation, timeout/recovery, expired artifacts and one largest supported synthetic input. Test rollback deliberately. These are cloud acceptance checks, **not claims made by local CI**. Set `LiveEnabled=true` to accept public submissions; it remains the operational on/off switch.

Keep the last known-good digest and parameter set. Roll back by updating **ImageUri on the same CloudFormation stack**, either rerunning a known-good commit's workflow or running the equivalent `aws cloudformation deploy` with that digest and previous non-image parameters. Do not register task definitions outside CloudFormation. Tagged images are retained automatically so the active/rollback images cannot age out; periodically remove obsolete tagged releases after checking active/rollback task digests. Untagged layers expire after seven days.

To pause model spending set `LiveEnabled=false` through CloudFormation and wait for replacement (quiet window). To stop task charges set `DesiredCount=0` through the same stack. The ALB/IP/log/image charges continue; delete the service stack when the deployment is no longer needed. ECR is retained by bootstrap deliberately; remove it separately only after deciding rollback is no longer required. A task has 120 seconds to stop; long runs are interrupted rather than resumed. Deleting/replacing tasks loses their local daily counters and artifacts.
