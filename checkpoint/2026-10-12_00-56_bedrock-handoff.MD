# ModelLM checkpoint — 2026-10-12 00:56 Australia/Sydney

## Purpose and honest status

The original request was a minimal end-to-end application that turns 2–5 uploaded CSV/Parquet files and a rough business question into a profiled DuckDB raw layer, an agent-produced Kimball-style `AnalyticalPlan`, agent-produced dbt models, validated DuckDB fact/dimension tables, agent-chosen BI views, and a deterministic Streamlit dashboard. This repository now contains that pipeline and a **passing deterministic sales demo**. It also contains a wired Strands/Amazon Bedrock path for uploaded data, but **no Bedrock inference or arbitrary-upload run has been tested**. Treat the latter as an implementation candidate, not a proven capability.

The code is at the repository root: `app.py` for Streamlit, `src/` for Python modules, `tests/` for the acceptance test, `pyproject.toml` and `uv.lock` for dependencies. Run outputs are ignored under `runs/<id>/`. Python 3.12+ is declared; local verification used Python 3.13, dbt-core 1.12.5 and dbt-duckdb 1.11.0.

## Exactly where the demo is predefined

- `src/demo.py:demo_plan()` returns the business objective, questions, assumptions, one sales process, two dimensions and one transaction fact. Changing the Request text while running the bundled demo does **not** change this plan.
- `src/dbt.py:demo_implementation()` returns `dim_customer.sql`, `dim_product.sql`, `fact_order_items.sql` and `schema.yml` with key, uniqueness, null and relationship tests.
- `src/analysis.py:demo_analysis()` returns four chart selections and generic finding text. The plotted data and metric values are still calculated from dbt-built DuckDB tables.
- `src/workflow.py:run()` selects these functions only with `demo=True`. With `demo=False`, it calls the three Strands functions in `src/agents.py` instead.

This split was intentional: a stable demo first proves ingestion, DuckDB, dbt, Plotly, UI and artifact flow without model variability or AWS access. It must **not** be interpreted as evidence that the Bedrock path produces an equivalent model.

## How to run the Bedrock path next

1. Run `uv sync --extra dev` in the repository. Configure AWS credentials and a region with access to a Bedrock model that supports this Strands streaming/structured-output path. The application uses the boto3 credential chain. Confirm permission for streaming model invocation; set `MODELLM_BEDROCK_MODEL_ID` if the current default `global.anthropic.claude-sonnet-4-6` is unavailable in that account/region.
2. Start with `uv run modellm-demo --bedrock`. This uses the *known synthetic files* but asks Bedrock for all three decisions. Alternatively start `uv run streamlit run app.py`, select Strands + Bedrock agents, and upload 2–5 related files. Uploaded files force the agent path regardless of the radio selection.
3. Inspect the generated `runs/<id>/result.json`, `dbt/models/`, dbt logs and analytical tables. Compare business process, atomic grain, join keys, orphan handling, measures, row counts and revenue with the deterministic baseline. A sensible result need not be textually identical, but unexpected data loss or changed revenue needs explanation.
4. Repeat this run and try several distinct small fixture families (for example invoices/lines/customers, subscriptions/events/accounts, and unrelated tables). Capture success rate, invalid plans, dbt repairs, elapsed time, tokens and cost. Only then decide whether the prompts and contract are adequate.

## Design rationale and trust boundary

The plan is a small modelling contract because the original request expressly sought business processes, dimensions, facts, grain, measures and assumptions without turning the plan into a SQL language. dbt owns transformations so builds can be inspected and repeated. Plotting specifications are constrained to validated table names, fields and a small aggregation vocabulary so the final dashboard queries are deterministic. The synthetic path removes LLM variance while testing the actual dbt and DuckDB work. A single repair bounds the initial spike's model loop.

These choices make failures visible, but they do not make the LLM trustworthy by themselves. Strands currently provides three streamed, schema-constrained model invocations, **not** autonomous data exploration with attached tools. Pydantic can accept a coherent-looking but wrong plan; dbt can pass tests that the same model generated; a chart can accurately plot a semantically wrong fact. Bedrock results should therefore be reviewed against source evidence and reconciliation checks until repeated agent-backed fixtures demonstrate reliable behaviour.
